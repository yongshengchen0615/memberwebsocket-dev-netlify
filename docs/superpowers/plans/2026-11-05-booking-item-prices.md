# Booking item price publishing Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans task-by-task. User authorized implementation, merge and Integrated-Marketing-Platform publication on 2026-11-05; do not pause for another execution-method approval.

**Goal:** 每個項目獨立立即／定時發佈新價格，保護舊預約與逐項報價。
**Architecture:** 價格事件表及依時間解析的 security_invoker view；不依賴 cron。六支獨立 -preview Edge 固定產生可信 context，原端點與實體 base 價格維持既有行為；Integration build 路由至 preview。交易內 snapshot trigger 最後核對逐項價格及版本，兩種預約明細都保存有效價格。管理員撤權／商家停用只撤銷未來價格事件。
**Tech Stack:** Existing Node 22/24, Deno, PostgreSQL 17, PGlite, JSDOM, Playwright; no new project dependencies.
**Spec:** ../specs/2026-11-05-booking-item-prices-design.md

## Global Constraints
- Preserve service IDs, historical booking snapshots, ticket/point/LINE contracts and tenant isolation.
- Price is integer NT$ 0–10,000,000; dates in Asia/Taipei, persisted timestamptz.
- No unrelated scheduler activation and no destructive production tests.
- Full existing three-workflow baseline must pass on the delivered commit, followed by deployed smoke.

## Review Focus
- Two opposite per-item changes must not bypass validation by equal total.
- Old client / non-price edit must not overwrite a newly effective publication.
- Same item same timestamp, cancellation races and idempotency must preserve final rows.
- A revoked admin's future events never revive after reapproval; past effective price does not roll back.
- Both booking_items and booking_participant_items must keep the same unit price and version check.
