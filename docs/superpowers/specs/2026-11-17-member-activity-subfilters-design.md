# 會員活動歷程細分類

## 目標與範圍
一般管理端「會員卡 → 使用紀錄 → 會員活動歷程」保留五個主分類，增加依現有資料欄位的細分類、數量與每筆分類標示。這是本輪對「再細分」的實作假設；不新增或臆造歷史事件。

## 第一性原理
| 項目 | 決策與不變條件 |
|---|---|
| 身分／權限 | 沿用 LINE 管理員登入、既有伺服器授權與商家範圍，不更動 API/RLS |
| 狀態 | 切換主分類或會員時重設細分類；即時更新保留目前細分類 |
| 資料 | 使用 event、recordType/entryType、ticketType、itemType、status 及取消申請欄位；未知值歸其他，不遺失資料 |
| 限制 | 基線 c09d8b5ab7b7f7875e04200a476f284141175e2b；僅 Integrated-Marketing-Platform / MemberWebsocket-test |
| 失敗 | 空分類、未知舊資料、缺欄位、快速切換會員、失敗回應、即時狀態變化、手機及鍵盤 |

## 方案
1. **採用：現有回應在前端細分。** 不增加請求、依賴或資料表；細分類顯示目前狀態，無法代表每一次歷史狀態轉移。
2. 擴充後端事件帳本。能追蹤完整狀態轉移，但需要資料模型、回填與交易改動，本需求沒有足夠依據採用。

## 顯示與分類
主分類下方提供原生下拉選單（含各細項筆數），並顯示篩選後／主類總筆數。全部主分類時停用細分類，提示先選主分類。各筆加上細分類標籤；切換細分類不發送 API 請求。

- 上／下線：上線、下線。
- 集點卡：管理員發放、獲得點數、兌換扣點、預約回饋、日曆回饋、點數調整、轉入、轉出、集點票券。
- 活動票券：優惠券、抽獎券、好友邀請券、加入會員券。
- 日曆：活動、休假日（僅既有票券關聯紀錄，不新增瀏覽追蹤）。
- 預約：待確認、已確認、取消申請、已取消、已完成、已拒絕、無故未到。
- 每類均保留其他；未知欄位不推定為已知事件。每個主類與全部均依 occurredAt 新到舊顯示。

## 驗收與證據計畫
| AC | Given / When / Then | 測試 |
|---|---|---|
| AC-001 | Given 五類混合資料，When 選細分類，Then 僅顯示對應資料且筆數正確，主類筆數不變 | Node 行為、Chromium 桌機／手機 |
| AC-002 | Given 未知、缺欄位及空分類，When 篩選，Then 未知歸其他、空類顯示空狀態，無例外 | Node、Chromium |
| AC-003 | Given 已選細分類，When 切換主類／會員，Then 重設；When 更新同會員，Then 保留且重算筆數 | Chromium、既有 stale-response 回歸 |
| AC-004 | Given 同一已載入會員，When 切換篩選，Then 不增加歷程請求，時間新到舊，輸入文字不作 HTML 執行 | Node、Chromium |
| AC-005 | Given 本輪最終 SHA，When 跑完整基線與建置，Then 保留各層實際 pass/fail/skip 與部署證據，必要缺項不記通過 | 既有三套 CI、build、測試環境 smoke |
