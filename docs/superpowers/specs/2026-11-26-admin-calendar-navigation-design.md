# 管理端日曆操作設計

目標：依提供的 24 秒影片，讓活動票券、會員活動、預約日曆具有一致的月份列、左右滑動、當日檢視與新增入口。基準為 `bd7f698a6303115134a51e799e997f7fbe06ffdf`，來源與 PR 目標為 `Integrated-Marketing-Platform`，資料環境為 `MemberWebsocket-test`。

已確認：現有三個月曆、資料快照、日期表單、活動／票券編輯與預約管理均可沿用。影片示範月份快速切換、點日期進入日時間軸、＋展開選單、選日期後新增。工作假設：套用操作模式與既有明暗主題；不複製 Google 的生日、工作待辦、邀請或視訊會議。

方案：保留現有月曆與儲存流程，新增一個共用的純介面控制器，三處各自保存檢視狀態。替代方案是引入完整日曆套件並重寫表單，會增加依賴與既有授權／日期語意的相容成本，因此採用前者（本輪實作決策）。

不變條件：活動票券只列票券；會員活動排除同步票券及休假；預約日曆只列預約與休假。切月、選日不新增 API 請求或寫入。儲存沿用原 API、商家及 LINE 授權、衝突版本檢查與 Loading。日期採台北今天／UTC 日期運算。日期型活動維持全天，不增加時間欄位。預約時間軸使用原開始／結束時間，跨夜須能看見前日延續。

| AC | Given / When / Then |
|---|---|
| AC-001 | Given 任一管理日曆，When 點月份列、選年月、左右滑動或回今天，Then 月份與日期正確，跨年不偏移，縱向捲動不切月。 |
| AC-002 | Given 月檢視，When 點日期格或以鍵盤啟動日期，Then 顯示該日全部項目／空白狀態，可切前後日並返回該月。預約依時間排列，保留重疊及跨夜資料。 |
| AC-003 | Given 所選日期，When 點＋與該日新增動作，Then 開啟原有票券／會員活動／休假表單且帶入日期；關閉不寫入；儲存仍可讀回及編輯。 |
| AC-004 | Given 既有項目及資料刷新，When 開啟、儲存或刷新，Then 仍使用原編輯與預約詳情流程，保留當日檢視且不跨日曆洩漏項目。 |
| AC-005 | Given 桌機、390px 及 320px 手機與明暗主題，When 以觸控或鍵盤操作，Then 文字可讀、控制項可用、不造成橫向頁面溢出、Escape 關閉新增選單且回復焦點。 |

測試：新增純日期／跨夜單元與真實 Chromium 操作案例，先確認舊版缺少新互動而失敗；調整舊瀏覽器案例的「點日期立即編輯」為新契約，保留原有儲存、讀回、權限及分類斷言。完整基線為三條 test workflow 的所有 job；外部真人 LINE 登入若無帳號不得當作驗證。無 DB／Edge／LINE 契約變更，不對遠端會員資料做寫入或破壞性測試。
