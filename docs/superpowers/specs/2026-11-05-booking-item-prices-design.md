# 預約項目：逐項價格立即／定時發佈設計

日期：2026-11-05（Asia/Taipei）  
狀態：已實作並完成審查修正；完整 CI 與部署結果以 PR 與交付報告為準。

本文件取代前一版「整套清單切換」設計。使用者已明確指定：每個預約項目可以設定不同價格的發佈時間，或者立即發佈。下列未由使用者指定的行為，標示為工程建議，不能當作已獲確認的需求。

## 最終實作與驗收邊界（優先於下方早期工程建議）

- 使用者授權實作、合併及發佈 Integrated-Marketing-Platform 供驗收。
- 沿用既有 preview 部署隔離策略：六支 booking Edge 部署為 `-preview` 端點，只有 Integration build 路由到這些端點。端點固定產生可信價格 context，呼叫者 body flag 無法關閉價格核對。
- Integration 價格事件先供驗收入口使用，正式 main 入口繼續使用實體 base price；不替換正式 Edge、正式 Netlify deploy 或既有預約價格。驗收後正式導入需要一起更新正式 UI 與 API。
- 以交易內生效時間 resolver + ledger 取代 tick/cron；不啟用原本停用的工作。不同項目、不同時間自動解析有效價。
- Preview 普通項目編輯只修改原有資料，價格欄 readonly；調價一律走「調整價格」。資料庫保留 raw base，避免名稱編輯帶入驗收價格。刪除仍取消其未來事件。
- 會員與管理員的單人／多人／電話改單皆凍結畫面呈現的逐項報價；改價後送出需409重新確認，不能用背景刷新版本默默成交。
- 已完成服務更正及連結既有預約的收據沿用歷史單價；新建回溯收據核對並保存當下有效價。只有伺服器列出的報價寫入 action 啟用新價格 snapshot guard。
- 撤銷 tenant、qualification、runtime admin 身分（含 role 降權／換 ID）時永久取消未來事件；已生效及歷史快照保留。刪除也涵蓋。
- 相同 schema 的價格／預約交易先取同一 advisory lock；遞迴涵蓋間接呼叫寫入的收據 wrapper；pre-request 在資格 SHARE 前取得商家價格鎖，平台控制 RPC 在入口先取得 public／排序商家鎖，再操作資格列。保留既有授權與函式簽章。

## 2. 第一性原理摘要與方案

| 項目 | 確認內容／工程建議 |
|---|---|
| 目標 | 管理員可以為單一預約項目設定新價格，選擇立即或未來時間發佈；會員使用已生效價格。 |
| 身分 | 沿用既有 LINE 驗證、管理員 session、資格與商家驗證。 |
| 權限 | 管理員只能操作自己獲授權商家的項目；會員不能設定價格或讀取未發佈價格。 |
| 狀態 | 價格紀錄有待發佈、已發佈、已取消、失敗／阻擋；各狀態及操作可追溯。 |
| 資料 | 服務 ID 穩定不變；金額沿用 NT$ 整數 0–10,000,000；生效時間保存 timestamptz。 |
| 限制 | 沿用現有前端、Edge Functions、RPC、商家 schema 與測試；不引入外部排程服務。 |
| 驗收 | AC-001 至 AC-012，包含立即、不同時間、重送、併發、權限、舊預約與舊畫面。 |
| 失敗 | 未到時間不得提前換價；價格核對失敗不得默默成立錯價預約；發佈不得改寫舊預約。 |

不變條件：

1. 項目 A 調價不能改變項目 B，也不能影響另一商家。
2. 未到生效時間仍使用原價，已成立的預約維持其已保存的價格快照。
3. 發佈與新建預約在資料庫內核對同一份有效價格；不能只在前端判斷。
4. 重送與併發不能造成重複紀錄、提前生效或部分更新。
5. 未登入、跨商家、無預約功能授權、停權／撤權管理員均由伺服器拒絕。

## 3. 操作與資料設計

### 管理端操作

在既有「預約管理 → 預約項目」中，針對每個項目提供：

- 目前售價。
- 「調整價格」操作：輸入新價格、選擇立即發佈或指定日期與時間。
- 待發佈價格、預定生效時間，以及取消／改期操作。
- 價格歷史：原價、新價、預定與實際發佈時間、操作者、狀態。
- 發佈成功後重新讀回價格；衝突或失敗保留輸入並顯示可處理的原因。

排程模式必須選擇有效未來時間；立即發佈由伺服器使用當下時間。時間統一標示「台北時間（UTC+08:00）」，不能受瀏覽器所在地時區影響。

工程建議：同一項目可排多個不同時間的價格，例如 11/10 起 800 元、12/01 起 900 元；同一項目同一生效時間只允許一筆有效待發佈價格。每筆可分別取消或改期。不同項目可以在同一時間生效。

工程建議：立即調價不自動取消該項目其他未來排程，操作畫面明示下一次排程；若要取消，管理員須明確操作。當項目停用時，允許已授權管理員管理其價格，但不因此重新開放預約；軟刪除時取消未來排程，不能由舊工作復活或改價。

工程建議：新增項目先設定一個立即有效的初始價格，再管理未來價格；不以未發佈價格讓新項目暫時變成 0 元。

### 生效規則與會員流程

發佈時間代表「新價格開始供新建立預約使用的時間」，不依會員選擇的實際服務日期選價。例如 11/10 發佈後新建 12 月的預約，採 11/10 當下已生效價格。此為工程建議的明確時間語意。

- 發佈後的新預約、時段報價與總價使用生效價格。
- 會員開啟畫面後遇到調價，送出時須核對每個已選項目的價格版本；若有變更，顯示最新總價，讓會員重新確認，不默默換價成立。
- 版本核對至少包含服務 ID、價格與有效價格識別；不能只比整筆總價，避免兩個項目漲跌互抵。
- 既有預約保留資料庫已保存的單價快照。發佈本身不改名稱、服務分鐘、點數／票券預留與 LINE 通知。
- 本輪不改寫既有「主動修改已成立預約」的重新計價規則；須先測出原有行為，再確認價格發佈沒有意外改變它。若發現現有規則會造成不一致，另以明確差異呈現，不能沿用前版提案中未確認的「整筆重算／純改期凍價」新規則。
- 服務 ID 與票券配對規則沿用現有契約；價格發佈不自動改綁票券、不重新發券或扣點。

### 最小資料與伺服器邊界

建議以一張逐項價格發佈表保存服務 ID、價格、生效時間、狀態、操作識別、revision、建立／更新操作者與時間、實際套用時間及不含秘密的錯誤碼。名稱供實作計畫確認，不視為已存在表。

- 同項目／同有效生效時間有資料庫唯一約束。
- 有操作識別及 optimistic concurrency 檢查，重送取得相同結果，過期變更回傳 409。
- 以同一鎖定順序處理服務、到期價格與預約報價驗證，避免價格套用與預約交易交錯。
- 既有單筆／批次改價必須納入同一價格與稽核邊界，避免繞過發布規則。非價格欄位編輯不得順便覆蓋另一位管理員剛發布的價格。
- 安裝須涵蓋 public、所有既有 business schema 與新商家 provisioning；保留既有服務 ID 及資料。
- 表啟用 RLS；價格管理 RPC 不開放給 anon／authenticated 任意呼叫，沿用現有 Edge 授權與交易內資格檢查。
- 管理畫面關閉、ID token 自然到期或一般登出，不取消已授權排程；不保存原 token。
- 到期再次確認商家及操作者仍具適用資格；停權、商家到期、移轉或功能撤權不得繞過。被阻擋後須明確重新排程，不因復權自動補發。

### 排程、補執行與同步

既有環境的多個排程處於停用，不能只新增一個未執行的 cron 定義就宣稱自動發布可用。

建議新增限縮用途的價格發佈 tick，配合業務請求到期檢查。清單／時段查價及建立／修改預約的交易必須使用一致的價格解析與版本核對；不是只在另一個交易先跑補執行就視為足夠。

- 不啟用或修改無關的舊排程。
- 相同項目多筆到期按生效時間排序處理；停機恢復時以最後一筆有效到期價格為現價，歷史仍有可追溯狀態。
- 單一商家失敗不能阻斷其他商家。
- 暫時性故障保留可重試狀態；當次無法確認有效價格的預約請求應失敗，不以不確定的舊報價成交。
- 確定資格／資料阻擋則明確標示，保留原價，不無限重試。一般讀取與新預約只在可確定當前有效價格時繼續。
- 明確顯示預定時間與實際套用時間；不宣稱故障時仍能精確到秒實體更新。
- 同步事件於交易成功後發出；價格發佈本身不發送預約 LINE 通知。

## 7. 執行與回復方式

後續實作依序：新測試 RED → 相容資料結構／逐項價格 RPC／tenant installer → Edge 與報價核對 → 管理端操作 → 新案例及完整基線 → 審查 → 指定環境部署與真實排程驗收。

- 沿用現有專案，獨立分支與 PR；實作前重查最新 HEAD。
- 不重寫已發布 migration，價格表與 RPC 先在隔離資料庫驗證。
- 取消待發佈價格可停止未來異動；已生效價格需以新的立即發佈紀錄回復，保留歷史。
