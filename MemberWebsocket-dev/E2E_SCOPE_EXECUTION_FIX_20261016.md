# E2E 全選執行修正（2026-10-16）

## 已確認問題

- 最近兩輪資料只留下 points 用戶端報告，沒有 paired root 報告。這能證實證據不完整，不能單憑這些紀錄判定使用者是否停止或瀏覽器是否暫停。
- 舊協同流程將任一預約前置失敗視為整輪失敗，取消其他已勾選頁面。
- 舊管理端節點逾時會設定全域 cancelled 並拋出例外，取消獨立用戶端。
- 正常取消及數個提早返回分支不保存 paired 報告，因此漏跑項目與自動停止原因無法回查。
- 執行鎖只有 1 分鐘；清除流程另以 90 秒心跳判定失效。背景節流存在意外失鎖風險，但目前紀錄不足以證明最近兩輪就是此原因。

## 修改與安全界線

1. 維護模式、有效管理員授權、測試資料與執行鎖仍為共同前提。只有管理員授權前置失敗會阻止所有用戶端；預約功能斷言失敗保留結果後繼續測試。
2. 管理端逾時先等待最多 5 秒讓原操作完成清理。原操作仍未結束時，後續管理操作與深度管理測試標記 failed / executed=false，獨立用戶端視窗可繼續；不重疊管理端寫入。
3. 原操作未結束前保留執行鎖，結束後才釋放；下一輪仍受 pending-node 防重入保護。
4. 取消／啟動失敗會保存中止原因、每個未執行管理節點及每位會員的未執行勾選頁面；不宣稱可完整重播、不算完整 root 演化成功。
5. API 將 acquire／heartbeat 租期統一為 5 分鐘，每 15 秒續租；資料庫兩個 purge overload 均只回收 expires_at 已到期的鎖。失效或其他 actor 的鎖不能續租。這項調整使放棄的 Runner 最多保留 5 分鐘鎖。

## 驗證

- 新增 coordinator 行為測試：1／2／10 人全選、預約前置失敗、用戶端錯誤、授權失敗、取消保存、逾時隔離及延後釋放鎖。舊版五項失敗，修正版通過。
- 新增 Chromium 測試：同一真實 popup 依序走五個勾選頁面，第一頁失敗後繼續；管理操作仍在清理時也覆蓋五頁。用戶端結果及 session transport 為隔離 fixture，非正式第三方投遞。
- 新增 SQL／API 整合測試：兩分鐘沒有心跳但租期有效時，兩個 purge overload 均拒絕清除；過期鎖不可續租、可回收；匿名／authenticated 不可呼叫清除函式。
- 執行 `node --test MemberWebsocket-dev/tests/*.test.js`、相關 DOM／SQL integration，以及既有 GitHub Actions 的全部測試 lanes。
- 本地 Chromium binary 啟動被執行環境以 SIGTRAP 終止；瀏覽器實測以 GitHub Actions 結果為準。

## 部署與回退

先套用 background_e2e_lease_grace migration 並部署 test-control-api，再更新前端 Runner 2026-10-16.1。沒有會員業務資料、表欄位、RLS 或驗證方式變更。

回退時一併回退 Runner 與 Function；若需恢復舊 purge 規則，使用前一版兩個函式定義，且先確認沒有進行中的 E2E。
