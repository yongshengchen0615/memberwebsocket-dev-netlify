## 根因與變更

一般管理端的 E2E 控制器採延遲載入，原載入器只監聽測試分頁的 pointerenter／focus／click。背景 Runner 雖沿用管理員 Session 並完成管理資料同步，卻沒有觸發上述操作，因此缺少控制器並持續等到 90 秒上限。以相同整合測試載入修改前的腳本，重現控制器請求數為 0；修正後自動載入並通過 Session→Bootstrap→控制器待命測試。

1. 帶有背景 Runner 與 run ID 的頁面自動載入控制器；一般管理端保留延遲載入與單一載入 Promise。
2. 載入器提供 idle/loading/ready/failed 狀態。網路失敗或腳本載入後沒有控制器會立即回報，不在輪詢中重複重試。
3. 主管理頁與 Runner 版本不一致時明確停止，避免舊快取靜默執行。
4. 啟動期間按停止後不再移交整輪測試；以 skipped 終態記錄。
5. 失敗視窗關閉前保存 adminReady、loader、controllerReady、版本、網頁狀態與最多 24 筆資源耗時；URL 只保留 pathname。
6. 優先擷取失敗 Runner 的畫面；視窗不可讀時明確標示 parent-admin 來源。圖片服務失敗會留下 screenshotCapture 狀態，保留原始錯誤。快照最多 2 張、每張上限 1.9 MB、12 秒期限；逾時會取消上傳並清除計時器。
7. 快照沿用私有 Storage 與管理員短期簽名存取，遮罩管理員姓名、會員識別與敏感欄位；不新增公開圖片 URL 或 Token 儲存。
8. 線上 test-control-api v24 比 main 少了實際 runnerVersion 與 Runner 生命週期診斷。同步已測試版本，並新增各啟動錯誤對應的檢查提示；不需 schema migration。
