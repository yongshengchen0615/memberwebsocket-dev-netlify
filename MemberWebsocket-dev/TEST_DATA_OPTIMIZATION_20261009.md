## 追加審查修正（PR #315）

- **可用時段稀疏／衝突**：不再只嘗試五個固定日期與時段組合。使用從測試識別碼導出的日期、時段巡訪策略，按不同日期分散查詢；為保護後端資源，單次 fixture 最多嘗試 96 個候選。超過上限仍可能回報前置條件不足，並非宣告整個月完全無可預約時段。
- **Fixture 建立中途失敗**：若建立票券後、建立對應預約時失敗，改由伺服器直接清理該測試會員與該 fixtureTag 的集點卡、發放票券、點數餘額、流水、獎勵與票券樣板，再回傳原失敗碼；若無法確認清理則回傳清理失敗。此修正避免尚未回傳 fixtureTag 時由於前端無法清理而留下殘留測試資料。
- **補充回歸**：新增「前五次時段衝突、第六次可成功」與「前置預約失敗時的所有 QA 集點資料清理」測試。驗證結果以更新後的 PR CI 為準。
- **部署順序**：先驗證所有 GitHub CI；合併 main 後再部署與程式碼一致的 `user-test-api`；最後讀取實際 Edge Function 版本。是否解決原三項失敗，仍須由已登入的測試 Session 重跑證明，不得以 CI 隔離測試取代線上 E2E 證據。
