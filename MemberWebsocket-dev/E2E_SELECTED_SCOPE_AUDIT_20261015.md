# E2E 選取範圍與雙端功能盤點（2026-10-15）

基準：main 28159fe；管理端／會員端 Runner 2026-10-15.1。

## 驗收契約

- 六個範圍：會員卡、集點卡、活動票券、營運日曆、整合中心、預約。63 種非空組合均以全節點模式規劃；seed／complexity 只影響順序與額外重播，不得抽掉已選功能。
- 每位測試會員均須執行每個勾選的用戶端頁面；整合中心只有管理端。1、2、10 人 × 63 組合的矩陣測試，逐一刪除每個用戶／頁面證據，確認結果轉為未完成。
- 功能表以外的新增登記節點也必須執行。缺少規劃、漏跑、略過、未知／中止狀態、失敗後的成功重送皆不能覆蓋失敗。
- 後端保存 selectedModules、scopeCoverage、每位用戶的頁面覆蓋、全部管理端節點及跨端交接缺口；缺少報告不能視為通過。未完成的 paired run 保存 failed 狀態及 incomplete 驗證狀態。
- 全部測試只操作測試帳號與本輪 QA 資料。LINE 收件、實體 GPS／相機權限仍需實機；contract／隔離 Chromium 不宣稱實際裝置或第三方投遞成功。

## 本次修正

## 執行方式與部署

單元／回歸：`node --test MemberWebsocket-dev/tests/*.test.js`。DOM／SQL：既有 GitHub Actions integration lane。瀏覽器：`npm ci && npm test`（tests/browser）；CI 新增優先執行本次七個 production runner 節點的驗證，並繼續執行完整 Chromium suite。

需同步部署 Supabase test-control-api 與 user-test-api；不變更資料表／RLS／業務權限。保留目前已採用的 LINE／測試 Session 驗證與 verify_jwt=false 設定。回退時一併回退兩個 Function 與瀏覽器 Runner 版本，避免前後端報告契約不一致。
